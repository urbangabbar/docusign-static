Review worksheet changes before updating CRM records

On this pagePreserve a valid matchInspect the proposed operationRecover without resending blindlyConfirm actual outcomes

By Karthik Anand · Updated October 16, 2026

Eligible updates to existing Contacts and Opportunities require Preview changes, Export Preview, and explicit confirmation. Editing a cell, changing update permission, or reconnecting an account does not automatically send outgoing updates.

Preserve a valid match

Use the imported worksheet’s CRM IDs and account context. Keep analysis-only formulas separate from mapped update fields. The service must verify the object, field definition, matching record, and current authorization before an update can be applied.

The reviewed-update flow does not promise arbitrary record creation, financial actions, message sending, or universal custom-object writeback. Use only the currently documented eligible fields.

Inspect the proposed operation

  1. Edit the intended supported worksheet values.
  2. Choose Preview changes.
  3. Review the matched records and old/new values in Export Preview.
  4. Resolve invalid cells, mapping issues, conflicts, and missing permissions.
  5. Confirm Update N rows in CRM for the displayed valid set.

A zero-change result should return you to the worksheet. It is not a reason to invent an update or bypass validation.

Recover without resending blindly

A stale review needs a fresh source check. A conflict requires a decision about the actual values. A disconnected account needs reconnection while preserving your draft. None of those conditions authorizes automatic outgoing writes after recovery.

For partial or uncertain outcomes, reconcile the original operation before another attempt. A retry of the same delivery must retain its operation identity to prevent duplicate effects and duplicate charges.

Confirm actual outcomes

Inspect the returned per-record results and, where appropriate, verify the changed values in the source. A completed preview is not a completed update. Keep unresolved failures visible rather than reporting the whole batch as successful.

Public samples cannot perform these operations. Production acceptance must establish provider behavior, current permissions, stale-review checks, and durable results before live use.
